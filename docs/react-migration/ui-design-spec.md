# 标题与辅助文案规范（Heading & Supporting Text Policy）

适用于 `web-react` 全部已迁移与后续新增页面。目标不是文字最少，而是每一行文字都有明确用途：标题建立层级，描述只在提供必要上下文时出现。

## 1. 基本原则

- 标题负责建立信息层级，描述负责提供必要上下文。
- 默认采用紧凑型标题：页面、卡片、模块、弹窗不自动配副标题或介绍性小字。
- 描述是可选能力，不是标题的固定组成部分；没有新增信息价值时省略。
- 判断标准：删除这句话后，是否影响用户理解当前状态、作出决策或正确完成操作？
  - 不影响：删除。
  - 影响：保留，并放在相关操作、字段或内容附近。
  - 涉及安全、不可逆影响：必须明确提示，不能为极简而删除。
- 禁止重复标题含义、套话式功能介绍和纯装饰文案（如“在这里管理……”“帮助你快速……”“本页用于……”）。

## 2. 各层级约定

| 元素 | 规范 |
| --- | --- |
| 页面主标题 | 一个清晰的 H1，直接表达页面职责；副标题默认不显示，仅在必要时提供上下文。 |
| 模块标题 | 简洁描述模块内容，不重复解释；动态状态、计数可保留在标题旁或内容区。 |
| 卡片标题 | 优先直接显示指标或业务对象，不配功能复述。 |
| 弹窗标题 | 明确操作及对象；标题已清楚表达目的时不加描述。必要风险、影响单独放在正文或确认区。 |
| 表单辅助文字 | 放在对应字段附近，而非页面标题下。 |
| 状态与错误 | 放在相关数据、操作或状态区域。 |

标题必须使用真实语义标签（`h1`/`h2`/`h3`），不能只靠加粗、放大字体伪装标题；标签文字应准确说明内容，满足可访问性要求。

## 3. 允许保留的描述

只有满足以下之一时才显示，并遵循就近原则：

- 操作前提：需先配对、服务端可访问、测试只使用已保存配置。
- 数据范围：当前版本、批次范围、筛选口径。
- 状态解释：离线、待补传、阻断原因、检测时间。
- 风险影响：删除、替换、发布、回收、中断、覆盖范围。
- 使用指引：空状态下一步、跨页选择保留、滚动步数入口。
- 字段约束：取值范围、格式要求。

放置位置：

| 信息类型 | 放置位置 |
| --- | --- |
| 字段约束 | 对应输入框下方 |
| 操作影响/前提 | 操作按钮旁或确认弹窗正文 |
| 风险/不可逆 | 确认弹窗正文与确认按钮 |
| 错误、阻断 | 出错位置或对应卡片状态区 |
| 状态、计数、时间、范围 | 状态行、徽标、列表筛选区 |
| 空状态指引 | 空状态区域内 |

## 4. 示例

不推荐（重复标题、无新增信息）：

> 任务中心
> 查看和管理所有采集任务，了解任务进度和运行状态。

推荐（标题直接连接操作与数据）：

> 任务中心
> 刷新 · 运行中 5 · 待检查 12

允许（说明影响范围与数据保留规则，放在确认框）：

> 批量回收分配
> 将回收选中的 24 家门店。已经上传的采集结果和历史记录不会删除。
> 取消 / 确认回收

## 5. PageHeader 契约

页面头部统一使用 `PageHeader`：

- `title` 必填。
- `description` 可选，默认不传；仅在确有新增上下文时传入。
- `actions` 用于页面主要操作。
- 标题使用 `h1`，页面内模块使用 `h2`，卡片内子分区使用 `h3`。

## 6. 新页面自查清单

1. 页面标题下是否只保留有新增价值的上下文？没有就删除。
2. 卡片/模块标题是否在复述功能？是则删除小字。
3. 弹窗标题是否已表达目的？是则不配描述；风险影响放入正文或确认区。
4. 每条描述是否能通过“删除后是否影响决策/操作”的判定？
5. 描述是否紧邻受影响的操作或字段？
6. 标题是否使用语义标签且层级正确？
7. 删除后功能提示、错误反馈、业务状态是否仍然完整？
