优先级 P0 表示阻塞对应阶段发布，P1 表示必须在相关模块验收前关闭或记录限制。以下为只读分析与安排，运行结果以 Phase -1 有证据的历史记录及后续隔离验收为准。

## 分阶段上线与回滚

| 关口 | 可回滚单元 | 回滚与核对 |
| --- | --- | --- |
| Phase 1 React 试点 | 预览入口与静态产物，与原入口隔离 | 退出预览回到同源现有 URL。React 资源或 session 异常时给出返回入口，普通用户可继续进入原页面。无 schema 迁移。 |
| Phase 2–4 分模块切换 | 同一发布中每个路由的归属清单、同版本 HTML 与静态产物，按冻结的入口映射验收 | 复用试点入口回退方案，仅保留当前过渡中需要的旧包。新业务协议须向后兼容旧 Worker，部署前保存现有发布版本及回滚清单。数据契约单独部署、各自验收。 |
| Phase 5 最终切换 | 可追溯的上一组 Windows 安装包与 Hub 镜像摘要 | 等当前采集轮次安全结束并通知用户后切换。使用现有部署机制回退完整应用发布版本，验证对应前端产物、配置和数据库兼容。若 #20/#21 改数据，必须在对应方案中明确前向迁移、旧端读取能力及必要的数据快照恢复条件。 |

任一切换遇到身份丢失、未上传包减少、历史不可读、非目标门店被改、越权写入或静态资源缺失均停止扩大 rollout。回退后重新核验连接、分配、逐店结果、待补传、审计和增量协议。实际生产升级、数据快照或回退动作需单独授权。
