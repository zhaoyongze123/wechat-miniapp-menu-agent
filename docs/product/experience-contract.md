# 全站产品契约

## 1. 信息架构与真实对象

导航采用现有角色内可用页面，顺序表达业务职责。Hub：采集工作台 → 素材清洗 → 质量审核 → 任务中心 → 采集电脑 → 分配记录 → 设置。Worker：采集工作台 → 任务中心 → 人工标注 → 设置；环境诊断从连接异常及设置进入，保留深链。远程控制从 Worker 半自动入口进入，不增加 Hub 远程执行权限。角色未知显示加载/失败，不默认为独立端。现有路由兼容保留；不新增仪表盘来重复各页统计。

| 对象 | 主显示 | 关联原则 |
| --- | --- | --- |
| 门店 | 可读名称、所属批次 | 批次内稳定 store_id，不用同名匹配 |
| 素材 | 已确认/待审核/不合格、门店有效素材版本 | 选码不是发布；批次发布记录不是所有门店版本 |
| 分配 | 采集电脑、分配状态、结果去向 | assignment_id，回收不删除历史；迟到结果按协议留档 |
| 采集任务 | 轮次名称、时间、进度、设备 | run_id，轮次包含多店；本机和 Hub 已同步结果不同 |
| 逐店执行 | 当前结果、当次证据、素材版本 | task_id + 真实执行/轮次身份，历史与当前有效记录不混 |
| 审核 | 待检查、不合格、人工确认、批次审核 | 审核事实由后台提供；不等于运行结束或同步成功 |

### 多项目范围（Issue #102）

- 项目是业务隔离边界，批次归属一个稳定 `project_id`；批次、门店、素材、审核、任务和交付记录按 ID 关联。项目名仅用于显示，可重名或修改；不得按名称、目录或二维码猜归属。
- Hub 业务页面以 URL `?project=<project_id>` 表示当前范围；本地存储仅记默认项目偏好。切换项目保留页面路由及筛选/详情上下文，并用新项目范围重新取数。无效或不可见项目显示明确空态，不回退展示其他项目数据。
- 已归档项目只读，可查看历史、证据、导出及派生交付视图；新增业务写入由服务端拒绝。项目选择器不是授权边界，服务端仍校验每个资源的归属和可写状态。
- 设备、连接、桌面互斥和当前活动运行属于实例级状态；活动任务摘要可显示其权威项目，不因切换工作区而改归属。新运行固定属于一个项目，可覆盖该项目多个批次。
- 历史记录只有存在可信项目关联时才归入项目；无法确认的历史数据保持待核验，不通过同名猜测迁移。

#20 强制：打回后该店立即停止新分配，保留历史；重新选码且发布后解除阻塞，不自动重采、不自动恢复旧审核结论。同图同尺寸/像素重发不升门店素材版本。重新采集不升素材版本。不同批次同名店独立。前端不自行推断业务资格。

## 2. 布局与信息密度

- 每页一个主标题；正常业务页面不加重复模块名、英文 eyebrow、宣传语或“此页面用于……”式段落。只有用户需要区分范围/风险时提供一句说明。页头右侧仅一个当前任务的高强调动作，其余为次操作、文字链接或明确的操作菜单；危险动作在独立确认中高强调。
- 列表页从上到下：页头及主操作 → 必要的范围/状态概览 → 筛选/搜索 → 有选择才出现批量动作 → 表格 → 分页。状态统计只有真实支持筛选时可点击；不要统计卡、筛选 Tab、下拉同时表达同一维度。不同真实范围不强合并。
- 采用公共 ResourceList/Detail 等模式（#58）；列表使用主内容可用宽度，避免所有宽表被过窄的全局 max-width 压缩；设置/短表单限制阅读宽度，画布和工作台优先可用面积。主要列表固定关键列和可达操作，长文本省略+完整查看；不为了整齐截掉真实信息。
- 详情从上到下：可读名称+关键身份 → 状态/最近时间/影响范围 → 当前结果或核心编辑区 → 历史、技术信息按需展开 → 持续可达的处置区。详情内部独立滚动，不套无意义卡片。宽屏图片工作区与普通详情不是同宽模板，画布优先。
- 顶部/底部固定区域不得遮挡证据/操作；1280/1024/768 CSS px 及常用缩放下可操作。窄屏单列按任务顺序重排，不隐去关键动作；次要动作可收进有名称的菜单。
- 首次加载、刷新失败、有旧数据、空集合、筛选无结果、无权限、离线、未同步、未记录不同状态单独表达。后台刷新不重置筛选、选中、滚动、打开详情或草稿。
- 跨页面交接携带真实稳定 ID 与返回上下文，禁止只填门店名/模糊搜索。列表→详情→操作→返回不重新定位。高频连续审核/清洗按用户偏好、真实成功进入当前筛选下一项；失败停在当前项，保留输入；到末尾明确当前范围处理完毕。

## 3. 操作及文案词典

| 用语 | 含义 / 约束 |
| --- | --- |
| 开始采集 | Worker 开始本机轮次；Hub 不能这样命名分配 |
| 分配给采集电脑 | Hub 分配当前选中的有效门店；不代表已开始 |
| 重新采集 | 单店重新执行；Hub 显示「分配重新采集」，Worker 显示本机动作；不自动改变素材 |
| 暂停采集 | 以现有真实暂停生效时机说明；区分正在暂停 |
| 终止本轮 | 停止本轮、保留已有结果，按后台提示未保存风险；不是删除 |
| 标记不合格 | 新建人工不合格结论，选原因与必要说明 |
| 确认不合格 / 取消人工确认 | 只改不合格的人工复核标记，不是标记不合格、撤销不合格或审核通过 |
| 撤销不合格 | 撤销不合格结论；实际任务恢复状态按后端，如未恢复可重采须明示 |
| 打回素材清洗 | 回到原批次重新选码、阻止新分配、历史保留；不等于撤销或重采 |
| 改为待检查 | 将当前合法结果交人工检查；不伪造已经过人工审核 |
| 回收分配 | 解除有效占用、旧结果留档；不保证离线设备立即停止 |
| 确认选码 / 发布已确认门店 | 前者只确定草稿决策，后者才影响有效下发素材 |
| 已截图待复核 | 有截图，不代表人工质量通过 |
| 已选码待发布 / 待重新选码 | 不混用「已确认」「可采集」 |
| 已分配 / 已下载 / 待补传 / 已同步 / 历史留档 | 各自真实事件；连接在线不推导数据已同步 |
| 批次审核通过 | 独立于门店选中集合，确认真实批次范围，按后台语义 |
| 更新已下载 / 待安装 / 正在切换 / 已安装 | 下载成功不等于运行版本更新；健康检查通过才成功 |

按钮使用动词+对象，保留产品熟悉的中文术语；避免「处理」「确认」「操作成功」这种缺对象的文字（上下文唯一的简短表单确认除外）。长 ID、路径、异常栈默认次级或折叠，复制敏感信息须脱敏。空态给必要的下一步（如无匹配→清除筛选）；正常状态不堆提示。错误格式「什么没完成 + 可理解原因 + 可执行下一步」，不把 HTTP 409、Python 类型名当业务文案。例：「该门店仍有有效分配，暂不能重新采集」应由后台资格支持；不要猜原因。禁用条件必须有可查看说明；权限不适用的动作不显示。确认窗标题用具体动作，正文只写对象/范围、直接影响、是否可恢复，按钮同名；普通查看、筛选、复制不用确认。

## 4. 功能保真优先于美化

旧入口、当前入口、最终入口必须可追溯。可合并相同业务组件，不得合并不同业务动作。任务详情等历史页默认只读历史；当能定位当前有效任务且有权限时提供当前门店处置；不能让用户误改历史或其他批次同名店。任何缺失资格应显示真实禁用理由或明确转到有权限的界面，不允许前端绕过服务端约束。业务层未提供完整证据时如实显示，不构造假状态/占位字段。
