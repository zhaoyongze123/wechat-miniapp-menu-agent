# Hub 采集工作台（/workbench）

用户任务：找到已发布且有资格的门店，跨页选择，分配给采集电脑，并了解占用和处理进度。不是任务历史总览，不在 Hub 驱动微信。参考 Prefect 的调度/执行分离。

本页列表、计数、筛选和批量选择都限于 URL 中的当前项目；每个批次只能属于一个项目，选择和提交由服务端再次校验。归档项目可浏览历史但不能分配。

```text
采集工作台                                      [分配给采集电脑]
门店总数 / 待采集 / 采集中 / 已截图待复核 / 待检查 / 不合格 / 待重新选码
采集电脑：在线、占用、待补传                         [查看采集电脑]
采集范围（仅真实不同范围） | 所属批次 | 状态 | 排序 | 搜索 | 清除筛选
[已选 N 家（当前页 M 家）  查看已选 / 清空 / 分配]
□ 门店 / 批次·素材版本 | 采集电脑 | 采集状态 / 原因 | 操作
分页
```

- 页面主操作为分配，未选时禁用并提示选择门店；批量条与页头共享同一动作状态，避免两个等权重主按钮；导入素材入口改为准确的「前往素材清洗」。统计维度如与状态下拉重复，保留一个主筛选交互并保证状态同步；范围/批次筛选必须分别有真实含义，不用两个模糊「全部批次」。
- 分配资格由服务端；不可分配门店保留原因，选择时仅可选项，保持跨页已选/300 家上限。改变筛选不静默清选择；明确有选中项在筛选之外；资格失效从有效选择移除并提示。
- 门店名称可读且可复制原名/ID，批次与素材版本有明确标签；设备列显示占用或未分配，采集状态与分配状态区分。点击名称/详情打开当前门店；不把失败详情直接跳到不相关同名门店。
- 已选门店抽屉：总量、名单、所属批次/版本、移除、清空、确认分配。分配弹窗：设备选择（在线/最近连接/占用）、选中总数与冲突、不符合资格原因、唯一确认「分配 N 家」。成功后仅移除已成功分配项；失败留选择。
- 门店详情：标题/批次/有效版本/状态与真实原因；原始二维码、当前有效结果证据；历史分配列表（时间、设备、结果去向、查看结果）。已授权当前任务可提供质量处置入口或定位到质量页的当前门店抽屉；具体动作见 quality.md；历史分配只读，不出现误回收/改历史动作。上一家/下一家按原查询，关闭回原列表。
- 恢复原 Hub 调试区域的折叠偏好，仅在开启调试时呈现最近活动；业务操作者无需阅读日志。保留 #30 已有只读身份校验。

验收：选择跨页 3 家、其中一条资格变化，分配前说明并保留其余项；设备离线/已占用时真实反馈；待检查门店从工作台可精确定位处置，无需搜索名称；打开历史不改变当前结果。
