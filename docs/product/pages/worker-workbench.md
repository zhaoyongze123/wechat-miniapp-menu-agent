# Worker 采集工作台（/workbench）

目标是本机采集员看清现在做什么，而不是把 Hub 调度页面套在 Worker 上。首屏当前运行优先于统计。

Worker 仅展示本机已知且获分配的项目及其任务；项目范围能力通过协议能力协商确认。旧 Hub 兼容时仍是固定历史单项目语义，不能从名称推断多项目归属。

```text
采集工作台                                [开始采集/当前轮次控制]
连接状态（未配对、离线、失效仅异常突出）           [同步状态]
当前运行：轮次·全/半自动 | 当前门店 | 已完成/总数 | 状态
[暂停/继续] [终止本轮] [打开置顶控制窗（半自动）]
半自动等待：当前指令 [开始截图] [标记不合格] [跳过]
本机门店概览 | 批次/状态/排序/搜索
□ 门店 | 状态 | 最近结果 | 最近更新 | 操作（详情/重新采集）
分页
```

- 无活动运行时使用一个简短空闲状态与「开始采集」；当前等待明确指令「请进入点餐菜单，完成后点击开始截图」。正在导航/截图/暂停时真实状态和禁用原因；终止与暂停不混。全自动暂停后切半自动仅在现有后端允许时出现。
- 开始弹窗：轮次名称、全自动/半自动选项的实际区别、选中家数、预检及阻塞原因；确认后才启动，失败保留选择与名称，不因取消关闭旧运行。不得隐式开始其他未选门店。按已有上限校验。
- 已配对离线与凭据失效分开：已下载有效分配按现有协议可离线继续；待补传文件与历史确认由后台同步，UI 关闭不停止。同步弹窗首行「待补传 N / 最近同步时间」，下方待补传、最近确认/留档、最近错误；只有真实重试能力才显示重试。
- 单店详情（WorkerTaskDetailDrawer）：名称/状态/批次·素材版本/本机任务身份；当前结果（二维码、失败画面、截图、原因），历史（有真实本机记录时显示轮次），诊断（debugView 下动作时间线、刷新、分页、运行选择、导出调试包）。已存在的查看、复制、证据预览必须保留。详情底部提供合法的本机重新采集，不要求退回列表。旧版「改为待检查/标记不合格/撤销不合格/打回」按角色/任务资格核对；配对 Worker 不增加 Hub 审核写权限，可提示「请在共享后台质量审核处置」及在已知合法 Hub 地址/稳定任务映射时提供精确导航。半自动当前等待的判退仍独立保留。
- 操作成功刷新本机任务/轮次/同步，失败停留当前上下文；不从 Worker 的本机 UUID 猜测 Hub 任务身份。

验收：离线已有任务可继续，重新连接保留待补传；半自动等待切入置顶窗口不停止任务；有权的重采在详情一步发起；旧诊断入口可用。
