# #24 Phase 0 Hub 与 Windows 原生采集端角色矩阵

以 `e6b7ea8` 为源码事实，以已确认的 Hub + Windows Worker 为 React 产品范围。此基线的后端和旧界面仍有 Standalone 和 UiPath 兼容入口。迁移只覆盖两种目标角色，新前端不提供旧执行方式选择，后端清理单独评审。Windows 原生路径仍使用现有采集执行器和 UI-TARS 适配器。

## 功能、权限与事实来源

| 能力 | Hub 管理员 | Windows 原生采集端 | 校验与事实来源 |
| --- | --- | --- | --- |
| 服务入口 | Hub 运营端与共享 API，部署访问按 Host 允许列表及 Basic 管理认证 | 本机 Windows 登录会话，loopback 端口 8765，浏览器打开本机服务 | `server.py:69–109,165–215`，`shared_routes.py:18–46`，`deploy/windows/Launch.ps1` |
| 角色、连接与状态 | 显示设备最近在线、待补传、最后一次运行摘要和当前活动分配；不能从这些字段推定完整跨设备历史 | 未配对、有效在线、暂时离线、配对失效四类；显示本机缓存、待上传、结果去向 | `/api/shared/status`；Hub 按 `last_seen` 与 `last_run.reported_at` 显示两种时效，Worker 按本机连接及协议反馈 |
| 设备管理 | 生成短时一次性配对码，查看设备、改名、改备注、解除配对、移除/保留历史 | 输入 Hub 地址、配对码和设备名完成配对；不管理其他设备 | `shared_routes.py:31–67`；稳定 worker ID，活跃分配阻止撤销，移除要求已撤销 |
| 发布与素材 | 管理批次、上传/选码/分析、发布快照、批次返工、批次改名/回收站/恢复/永久清除 | 素材页面隐藏，素材写请求 409；处理已分配二维码 | `materials.py`、`material_versions.py`、`batch_management.py`；Hub 的本地文件选择动作受限，浏览器上传可用 |
| 门店工作台 | 多批次查询、筛选、跨页选择、分配/回收；以服务端资格为准 | 仅本机已下载且仍有可用分配的工作清单，按本机批次与状态展示 | `workbench_page.py` 与 `SharedWorker.tasks/check_start`。Hub UI 的 `current_task_id` 兼容旧快照关联，保留不可变分配 ID |
| 开始采集 | 禁止驱动本机或远程采集电脑的窗口 | 全自动与半自动、查询进度、暂停、恢复、终止；半自动手动截图、判退、跳过 | `server.py:187–199,1252–1410`；权限与执行窗口由 Python/Win32 校验 |
| 采集进度与历史 | 本地素材分析、已有 Hub 历史以及真实设备上报。#21 才提供完整 Worker 运行索引与同步详情 | 读取本机轮次、逐店快照与证据，允许按原 run ID 改本机采集任务名称 | active/history/rename 接口；Hub 可修改的本地历史与尚未存在的远程镜像权限应在 UI 明示 |
| 质量审核 | 不合格、待检查、人工确认、撤销、返工、批次审核、证据与导出。重采操作转共享分配 | 大部分审核写请求 409，直接访问相关读取接口与导航隐藏是两个层面。已分配/可运行任务需要再采时从正式本机执行入口提交 | `server.py:194–199,1510–1674`；半自动与标注产生的本机判退通过结果上传，和 Hub 人工复核分属不同事实 |
| 人工标注 | 无标注执行入口，写请求 409 | 以本机可执行分配启动标注，微信窗口操作与自动采集互斥 | `server.py:1755–1864`；后台管理可以读取获授权的历史/证据接口，React 按业务页面需要呈现 |
| 设置、用量与诊断 | 保留 Hub 模型配置、连接测试、模型用量、共享设置。禁止本机目录弹窗及 GUI 运行控制 | 本机模型参数、输出目录、原生桌面参数、微信环境与模型检测、使用量 | `server.py:342–421,1163–1219,1379–1395`；模型配置按实例保存，API key 不回传 |

## 项目范围（Issue #102）

| 能力 | Hub | Worker / 独立端 | 边界 |
| --- | --- | --- | --- |
| 项目目录 | 管理员可创建、改名、归档和恢复项目；业务页面按稳定 project ID 切换 | Worker 读取服务端已同步且分配给本机的项目目录；独立端固定使用历史单项目 | 项目选择是工作区范围，不替代服务端鉴权；项目 code 是路径身份，名称仅展示 |
| 项目业务数据 | 批次、素材、审核、任务查询及交付按项目过滤；跨项目新运行不允许 | Worker 只执行明确绑定到其项目的分配；旧协议兼容限定在历史单项目模式 | 归档项目只读；资源归属不一致或未知时拒绝操作，不按名称猜测 |
| 实例级状态 | 可查看共享设备、配对和运行状态；活动任务保留自己的项目身份 | 本机设备、连接、桌面锁和运行互斥仍为全局 | 切换项目不改变设备身份或正在运行的任务归属 |

## 分配、离线和结果的状态矩阵

| 时点 | Hub 可陈述的事实 | Worker 可做的事 | UI 反馈及错误边界 |
| --- | --- | --- | --- |
| 未分配/新分配 | 生成 `assignment_id`，状态 assigned。任务可能已被占用、需要返工或版本失效 | 取任务、验证源图字节并登记，持久化为 ready | 「已分配」与「已下载」分开；业务 409 展示冲突及目标设备。提交失败保持原选择。 |
| 已下载 `ready` | 收到 ready IDs 后确认下载；上报延迟时显示旧戳 | 按现有配对及门店资格启动全自动或半自动 | 二维码 SHA-256 可复用缓存，但不同分配 ID 独立，缓存文件存在也需登记。 |
| 运行中或暂停 | 仅在真实报到时更新设备摘要，Hub 不发桌面控制 | 已下载的有效分配可在断开 Hub 后继续，重启按照现有恢复规则处理 | 连接 Hub 断开、浏览器至本机服务失败、模型不可达、配对失效四类分离。无互联网时前端可打开，依赖远端模型的具体操作仍按实际可用性反馈。 |
| `pending_upload` | 只能看到上次上报的待上传数或还未收到 | 本机结果/outbox 已持久化，后台重试，与浏览器是否打开无关 | 「本机已完成」与「Hub 已接收」分开；刷新不发起重复运行或丢弃失败结果。 |
| `completed` 且 accepted | 结果与当前任务、源和版本仍匹配，应用当前门店结果 | 收到 ACK 后更新本机状态并清理对应待上传包 | 已同步可查证据。历史/状态读取展示当前版本及稳定身份。 |
| `reclaimed` 或结果 history | 回收后保留原归属。失效/被回收的迟到上传保留为历史，不写入当前任务 | 下次同步更新分配。旧结果按协议可补传，是否接受由 Hub 裁决 | 回收不等同于即时通知离线 Worker；确认中说明已有动作/结果保留，重新分配用新 ID。 |
| 已解除配对 / 移除 | 稳定 ID 与历史保留；凭证轮换，解除配对与归档分开 | 设备收到 401 后识别失效，禁止用旧资格开始，保存已有本机结果和待上传 | 不显示失效设备可分配。不用离线推断待上传为 0，也不清理本机数据。 |

## 数据域隔离

- **设备、分配与运行** 使用 `worker_id`、`assignment_id`、`run_id`。一个轮次可覆盖多店及多个批次。设备名称和门店可读标题用于显示，关联时使用稳定 ID。
- **素材与审核** 区分 `batch_id/store_id`、批次快照、任务、明确的逐店采集结果与人工审核。基线按有效快照筛选，店级版本与打回资格由 #20 业务契约提供。前端禁止用目录、名称或文件哈希代替长期门店身份。
- **不同物理事实源** Hub 共享存储、Worker 本机队列与历史、进程状态与设备最后上报各自有明确来源。缓存保留最近有效数据的时效，不伪造批次通过、完成、在线或空结果。
- **路由级验收** 用 Hub 管理员浏览器、未配对 Worker、已配对 Worker 在线/离线/失效分别测试深链和直接请求。验证平台屏蔽、401 与 403、业务 409、下载与证据授权。每个状态至少保留一项真实响应或浏览器录屏。
