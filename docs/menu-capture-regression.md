# 菜单采集问题与回归台账

按固定链路记录问题发生的位置，再用截图、动作和结果确定原因。同一个问题编号贯穿历次版本。Agent 继续自主决定小程序里的操作和业务终态，台账用于排查、复测和提炼通用经验。

## 1. 流程树

```text
扫码点餐采集
├─ 01 素材准备       选中本轮门店图片 → 校验素材和二维码候选
├─ 02 微信发送       确认文件传输助手 → 粘贴门店名与图片 → 确认发出
├─ 03 图片预览       定位本轮消息 → 打开并核实预览 → 找到二维码入口
├─ 04 扫码启动       触发识别 → 发现本轮新窗口 → 取得稳定首帧
├─ 05 Agent 导航
│  ├─ 观察           直接菜单、欢迎页、加载、空白、错误提示或独立弹窗
│  ├─ 行动           找入口、选人数、处理遮挡或授权、等待、切换窗口
│  └─ 交接           真实且无遮挡的菜单，或有证据的不可采／待复核
├─ 06 滚动与发布     校验窗口和菜单区域 → 滚动取图 → 保存与发布
└─ 07 店间交接       关闭本轮窗口和弹窗 → 复核微信安全起点 → 开始下一店
```

每个样本记一个主问题。执行中暴露的次要问题和跨店影响可以关联同一门店，统计门店数时只算一次。把**现象**（例如“点击后没变化”）、**已证实的原因**（例如“落点在按钮外”）、**待验证的原因**（例如“弹窗未接收输入”）分别记清。

## 4. 两项重点的验收口径

### 加载与慢响应

| 出现位置 | 应记录的证据 | 复测覆盖 |
| --- | --- | --- |
| 扫码后尚无新窗口（04） | 扫码动作回执、操作前后窗口列表、新窗首次出现时间、超时截屏。 | 快速打开、慢开、明确识别失败。等待和窗口发现属于执行链路。 |
| 已打开小程序（05） | 首帧、加载标志或部分渲染、等待前后帧、弹窗是否独立、何时出现可交互内容。 | 慢加载、局部渲染、稳定白屏、独立授权框遮住背景、明确服务错误。给 Agent 新帧，由它决定等待、尝试入口或结束。 |
| 滚动后内容暂未更新（06） | 同一窗口内的滚动落点、区域差异、重新截图时间、最终稳定画面。 | 菜单滚动后延迟渲染、已到尾部、滚动命令没有推动内容。 |

优先按真实执行样本统计从扫码到新窗口、从首帧到可操作、从滚动到稳定画面的耗时。首帧看见菜单可直接继续。加载样本保留至少一次有意义的重新观察，再用后续复跑的数据决定等待预算。持续异常且缺少明确业务证据的样本保留待复核。

### 门店交接与窗口归属

1. **开店前确认起点。** 记录本轮微信窗口身份和文件传输助手状态，记下运行前已有窗口。
2. **记录本轮打开或接管的窗口。** 关联预览、小程序和附属弹窗的窗口标识与所有者。受控窗口来自本轮启动或显式接管，收尾只关闭有归属证据且允许关闭的窗口。
3. **在退出路径统一收尾。** 成功、失败、异常、终止，以及按现有语义需要退出本店的暂停路径，均验证清理。对可确认归属的遮挡弹窗，尝试安全取消或关闭，再关小程序及预览。收尾不点击授权来换取窗口关闭。
4. **复核后放行。** 重新发现窗口，确认本轮窗口与附属弹窗已退出，微信已回到预期会话且可开始下一店。失败时保留前后窗口列表、关窗回执和末帧，继续按现有安全边界阻止串店。

验收必须用连续批次。让第一家分别留下预览窗、普通小程序窗和位置授权弹窗，在同一批次中紧接一家具备正常菜单的门店。记录是否自动完成交接、是否误关原有窗口、是否误开上一店及收尾耗时。命令回执成功后仍需确认窗口消失。

### 下一轮顺序

1. **固定流程先处理。** 统一统计口径，验证窗口关闭与安全起点，补足二维码右键菜单的可见证据。先回归误发布 E1624，并用真短菜单验证滚动证据，评估以页数拦截发布的替代方案。
2. **用实跑补齐导航证据。** 对照原图、模型点位、窗口映射及实际命中。把目标选择错误、坐标偏离、命中后无响应和加载延迟分别验证。用少量真实成功门店保持正常耗时基线。
3. **将确认过的共性提炼到现有 Skill。** 可复用的经验包括看见加载时再观察一帧、确认控件的可用状态、解决遮挡后重看菜单、按授权范围操作、区分打烊与菜单不可浏览。工具和统计问题留在对应执行层。Prompt 与工具改动分别复测，便于判断收益来源。

架构与验收边界见 [长期开发与优化规范](gui-agent-development.md)。

- 保留正式运行 ID。若中断，记录阻塞门店、当时的窗口、已做的人工操作、续跑的新运行 ID。统计按门店去重，并保留每次尝试和跨店影响。
- 跑完先对齐每家执行结果和实际发布目录。按主流程节点归类，再关联次要问题。对授权和点击留前后帧与点位，对加载留等待时长，对交接留关闭前后窗口列表，对少页与疑似误发布留发布图和交接图。
- 使用已有编号归类。出现新现象时先写证据和待核原因，确认确有新类型后再新增编号。另列样本数、复现数、错误发布及批次中断次数。
