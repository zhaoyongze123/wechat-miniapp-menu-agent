# 菜单截图：UiPath Mac 首轮联调版

这是本次改造的业务项目。`Main.xaml` 是正式代码的执行入口；`EnvironmentCheck.xaml` 只验证运行环境。原 Windows 项目没有被覆盖。本版尚未完成真实微信端到端验收，请先采一家店，再测有限批次。

## 两部分各做什么

- UiPath Studio 开发、调试并运行 `Main.xaml`，负责窗口截图、定位、单击、滚动、输入和快捷键。Assistant 是后续发布后的运行入口，本轮先在 Studio 调试。
- `../UFS_Menu_Scraper/macos_runner` 是本机配置服务：提供管理页、模型配置、图片扫描、任务状态、截图分析、输出归档。它通过本地命令文件与 UiPath 通信，不用 Python 模拟鼠标键盘。
- 输入每张图片都有稳定任务编号与内容摘要。输出为“来源文件夹 / 任务编号 / 本次尝试”，不使用“美团点餐”等小程序标题命名，也不覆盖历史尝试。

## 用户第一次操作

本机目前已接入 CLI 自动启动：管理页“UiPath 目标配置 → 启动方式”可选“由控制台通过 UiPath CLI 自动启动”。选中素材并保持对应小程序打开后，点击“开始采集”，服务自动传入本轮运行目录；不再要求手动填写 `in_RunDirectory` 或切到 Studio 点运行。Studio 手动模式保留给调试使用，以下标注步骤仅适用于首次配置新的窗口目标。

真实环境需分别给 UiPath Assistant 和 UiPath UIAutomation 录屏/辅助功能权限；配置服务自身的权限不能代替它们。截图、点击前由 UiPath 将目标窗口置前，实际坐标按窗口左上角和当前截图比例映射，鼠标用硬件事件。菜单准备阶段由模型判断页面含义，本地 OCR 校正明确按钮位置；人数确认还核对实际选中人数。活动桌面仍需保持可用。

先在管理页左侧进入“素材清洗”：

1. 选择本机素材目录后点“导入本机目录”，或选择整个文件夹后点“上传素材”。浏览器上传只发送到本机服务，保留门店文件夹层级；原图不覆盖。支持 JPG/JPEG/PNG/WebP，单张最多 50 MB，每批最多 10000 张、2 GB。
2. 点“开始分析”。Apple Vision 在本地检测和解码普通 QR，按码内容哈希分组，再结合码尺寸、边缘清晰度推荐同码照片。质量分只是启发式排序，不是扫码成功率。不同码、太小或无法检测的情况保留人工判断。
3. 左侧逐店选择，右侧对照原图和候选局部图，选择一个后点“确认候选并下一家”。也可跳过、撤销或重新选择。没有检测出二维码时，可在原图上拖框圈选；该手动框尚未本地解码，需微信验证。明确的自动推荐可一键接受，未知门店不会因此被自动确认。
4. 点“发布已确认门店”。只把已确认的店生成每店一图的输入快照并加入采集队列，未确认和已跳过的门店保留在清洗批次。发布相同决策不会重复建任务；修改选择后会生成新版本，不覆盖历史。采集运行中不可切换输入快照。

自动推荐、人工确认和微信验收是不同阶段。可解码的码仍可能是付款码或失效入口；普通 QR 检测也可能漏掉微信专用小程序码，“未检测到”不能等同于“原图没有码”。完整解码内容不保存，只保留哈希用于判断相同/不同码。

需要离线执行时，配置服务目录仍可运行 `python -m menu_capture.preprocess --input <原图目录> --output <尚不存在的新目录>`（使用该目录的 `.venv/bin/python`）；正常使用优先走管理页。目录选择、分析、确认和发布均不会触发微信点击。

1. 双击配置服务目录中的 `启动菜单采集.command`，保持终端运行。手动在浏览器打开 `http://127.0.0.1:8765`。已启动时只需刷新网页。
2. “配置”里检查来源和输出目录、模型设置。已有密钥不用重填；需要换密钥时在页面保存即可。
3. “总览”扫描素材。先选“单店接管”，指定一张素材，在微信手动识别并打开这张图片对应的小程序，调整窗口大小。
4. 在 Studio 打开本目录的 `project.uiproj`。通过目标标注工具取得小程序**整个窗口**的完整 XML 选择器，贴入管理页。不能只填店名。Mac 选择器结构以你实际标注结果为准，不能照抄其他机器。
5. 确认 UiPath 对应组件拥有 macOS“辅助功能”和“屏幕与系统音频录制”权限。在 Studio 做一次目标标注与坐标检查：截图覆盖整个窗口，坐标原点一致，选择器只匹配当前目标。然后在管理页勾选校准确认、保存。
6. 准备好 Studio 的 `Main.xaml`，在管理页点“准备采集任务”。页面显示本轮 `in_RunDirectory`。将此路径填入 `Main.xaml` 的同名输入参数，在 5 分钟内运行该文件。不要运行 `EnvironmentCheck.xaml`。本轮结束后 Main 会收到 stop 并退出。
7. 查看任务状态和输出截图。先检查有没有漏菜、重复过多、错店或分类没覆盖。调试期间保持桌面前台可用，避免移动/缩放窗口或同时操作鼠标。

## 单店通过之后

改成“自动打开二维码并逐店处理”，还需在 Studio 标注微信主窗口与图片预览窗口的完整选择器，校准输入区位置及快捷键。预览工具栏的“识别二维码”图标由本地视觉匹配定位，无需按钮选择器或固定坐标。开始前手动停在“文件传输助手”。先用每批 1 张，再测 2～10 张实验批次。一次只用一个 Studio Main、一个控制台采集任务。

自动链路：核验文件传输助手 → 发来源名称和任务编号 → 粘贴并发送图片 → 在本轮编号下方定位唯一二维码 → 右键识别 → AI 处理明确可关闭的广告、人数选择及菜单入口 → 连续确认菜单稳定 → 回到列表顶部 → 滚动截图 → 保存来源证据 → 关闭当前小程序 → 下一张。超时的点击不会自动重发。

配置页的“自动同意进入菜单所需的隐私协议和授权”开启后，模型和执行层允许自动同意隐私协议、必要权限、手机号快捷授权及微信快捷登录。无法自动完成的验证码/登录会保存现场；自动批次在关闭该小程序并确认回到文件传输助手后继续下一家，不要求逐店人工确认。开关关闭时保留原授权阻塞策略。身份无法确认、二维码定位失败、窗口尺寸改变等执行上下文异常仍会停止批次，不能宣称任意页面都能自动通过。暂停不能撤销已经执行的点击；会阻止后续指令并通知 Main 退出。

## 当前验收范围和已知限制

- 已通过官方 UiPath validate/build、真实 UiPath noop/延时/stop 指令收发，以及后台自动化测试。已用配置的真实模型验证生成的菜单测试图；这不等于微信实跑成功。
- 原始照片中有很小、倾斜或多个二维码。离线抽查 3 张，Apple Vision 仅在其中 1 张检测到二维码；聊天缩略图可能更难识别。当前自动模式严格要求本轮编号下方存在唯一可检测二维码，检测不到会停；图片放大和消息气泡定位尚待真实微信联调后完善。
- 当前只截一个连续滚动列表。出现“分类切换后各自独立列表”的小程序时，不能把列表到底视为全店菜单采完。输出 `coverage_verified=false`，隐藏分类和完整菜单仍需复核。
- 当前通过滚动步数控制重叠，不能保证不同小程序上固定的重叠百分比。“窗口宽高 / 重叠比例”配置暂时预留，未接入当前 UiPath 执行流程；窗口先手动调整。
- 连续三次画面不变只是到顶/到底的候选条件；滚动选区不对也可能不动，真实截图覆盖必须验收。达到最大页数仍未确认到底会转待复核。
- 模型调用及点击映射仍需真实窗口验证。前台桌面被占用、锁屏、微信掉线、不可读店名都可能中断；本轮不宣称已支持无人值守通宵运行。
- UiPath 工程采用 Portable 兼容性，后台职责已分离；Windows 的本地 OCR、剪贴板、选择器、快捷键和服务进程锁尚待适配和实测，不能直接宣称跨平台已验收。

## 本地检查

配置服务目录执行 `uv run --frozen pytest -q`。UiPath 项目使用已安装的官方 CLI 执行 `uip rpa validate --project-dir <本目录> --min-severity error --output json` 和 `uip rpa build <本目录>`。这些命令不证明微信业务验收完成。

密钥存于配置服务的 `secrets.local.json`，权限 0600；不要把此文件发到聊天、提交代码或加入交付包。
