# 点餐小程序导航经验

目标是浏览本轮门店的菜单并交接。根据截图自主选择动作。浏览期间避免登录、入会、储值、加购、下单、支付或发起外部联系。

## 一、三个终态怎么分

### success
已经出现可直接截图和滚动浏览的真实菜品菜单，通常能看到对应价格，且 `menu_box` 能框住当前可见的菜品列表。达到条件即可交接，滚动采集由程序完成。

可以判 success 的情况：
- 一两道菜也算，不要求菜品很多。
- 截图里没有显示店名时，如果开窗和导航过程能对应本轮门店，仍可交接。
- 页面显示的是其他分店时，只要已经出现可截图、可滚动的真实菜品菜单，就照常交接，不因店名不一致拒绝；店名不一致本身不是失败理由。
- 门店打烊、暂停接单，但菜单仍能浏览，也算 success（后续只截菜单，不下单）。
- 顶部横幅、分类导航、底部购物车或角落提示未挡住菜品列表和滚动时，可以交接。
- 覆盖在菜品列表上的广告、会员、储值或活动浮层必须先关闭再交接。不能因为浮层背后还能看到部分菜名和价格就判 success；交接前应确认浮层已消失。

不要判 success：
- 只有欢迎页、“立即点餐”按钮、门店介绍、广告。
- 只有分类名或搜索框，还没有菜品和价格。
- 购物车、订单确认、订单详情、历史订单、已下单成功页、支付页、开票页。这类页面即使列着菜名、价格和“加菜/再来一单”按钮，也不是可采集菜单。
- 页面正在加载或白屏。
- 模态弹窗盖住菜品区域或拦住列表滚动，即使背景有菜名和价格也先尝试安全关闭，重新截图确认。会员礼遇、储值海报、全屏广告都可能遮挡。合理尝试仍无法清除时，返回 needs_review。

### unqualified
要有清楚、可见的证据表明本轮拿不到菜单，而不是“暂时没成功”。

常见证据：
- 明确提示扫码点餐服务已关闭，且页面没有查看菜单的入口。
- 明确要求到店后再扫码点餐，当前没有可浏览菜单或可走的菜单入口。
- 明确提示二维码失效、小程序停止服务或门店未配置菜单。
- 页面明确写暂无菜单/暂无菜品，且重试或刷新后仍一样。

不算 unqualified：
- 打烊但菜单可见 → success。
- 提示暂时无法下单，但有“查看菜单/进入点餐”入口 → 继续。
- 白屏、加载慢、一般网络异常或提示重新打开小程序 → 有安全重试入口时做有限恢复，有加载迹象时观察等待。持续失败、没有可用恢复入口或无法确认是门店端故障时，返回 needs_review。
- 点击没反应、弹窗关不掉、需要登录、页面归属不明 → needs_review。
- 菜品很少、店名不全 → 不影响 success。

### needs_review
合理尝试后仍然无法确定：
- 强制手机号 + 验证码，无法跳过。
- 持续白屏或一直加载，多次等待仍无内容。
- 打开的页面与本轮二维码关系不明。
- 工具连续失败、窗口反复被拒绝。
- 弹窗无法消除，页面卡在中间状态。

## 二、常见页面怎么处理

- 欢迎页或广告页优先找能直接通向菜品菜单的入口。页面同时有点餐、会员中心、储值、外卖或商城时，结合按钮与页面内容选择菜单路径。误入无关页面后，优先找退出、返回或切回原窗口的方式。
- 全屏广告、会员礼遇、储值海报等有叉号、关闭、跳过入口时，先点这些入口关闭，再观察最新页面；不要未关闭遮挡就反复点底部导航。
- 门店首页是海报加人数选择时，按任务人数选中后，点底部的“开始点餐/去点餐”一次；没有页面变化时先核对按钮位置和选中状态，再决定是否重试，不要连续点海报或空白区域。
- 扫码后直接进入已有订单、订单详情或当前餐桌的点餐记录时，不代表无法采集。可按实际页面自主选择探索方向，不要求固定顺序：
  - 用返回、关闭或页面左上角返回箭头离开订单页。
  - 切换底部“菜单/点餐/首页”等点餐导航。
  - 找到仅用于打开菜单的“继续点餐/加菜/再来一单”入口，进入菜品列表。
  - 全程只浏览，不勾选菜品、不修改已有订单、不提交订单、不支付。
  - 以上方式都无法回到可浏览的菜品列表时，返回 needs_review，不要停在订单页。
- 订单详情、历史订单或下单成功页中的菜名与价格，不是菜单成功交接的充分证据；必须真正回到可滚动的菜品列表才判 success。
- 选择人数时优先选任务给出的人数，没有对应数字时可选最接近的可用项。确认选中状态后，再点击可用的开始点餐或确认按钮。
- 遇到隐私或授权弹窗时，优先使用可跳过、关闭或拒绝的入口。有些按钮有前置复选框，按页面含义和本轮授权判断。若只能通过手机号、登录或未授权的个人信息请求，返回 needs_review。
- 系统通知弹窗优先拒绝或关闭。
- 等待应有可见依据，例如加载提示、转场或刚触发的页面变化。等待后重新观察。有稳定的非目标页面时，转向返回或其他入口。
- 点击没反应时，对照动作前后的截图，看按钮是否可用、有没有前置条件、点击是否落在目标上。只有新证据支持时才重试同一位置。
- 点击点餐后，如果原窗口停在加载页、浏览器跳转页或没有明显变化，先用 `list_windows` 核对是否另开了微信小程序，再决定是否待检查。窗口标题只是线索，即使名为会员中心，也可以用 `switch_window` 查看合理候选的新截图。根据实际页面确认门店和点餐入口。

## 三、交接时的注意事项

- `menu_box` 只框菜品列表区域，不要包含顶部状态栏、底部购物车栏。
- 只框当前截图中可见的部分，不推测滚动后的区域。
- 理由写实际观察到的内容，例如“已进入菜单，可见菜品与价格”，不要写推测。
