# 点餐小程序导航经验

这是一份可参考的业务经验，不是硬性规则。请结合当前截图自行判断；如果与本轮实际页面冲突，以截图为准。

## 一、三个终态怎么分

### success
已经出现可正常浏览的菜品菜单，能看到真实菜品，通常带有价格；`menu_box` 能框住菜品区域。

可以判 success 的情况：
- 一两道菜也算，不要求菜品很多。
- 截图里没有出现店名，但菜单和价格清楚，也算。
- 门店打烊、暂停接单，但菜单仍能浏览，也算 success（后续只截菜单，不下单）。
- 菜单顶部有分类、横幅、广告，菜品和价格在其下方，按菜品区域框选即可。

不要判 success：
- 只有欢迎页、“立即点餐”按钮、门店介绍、广告。
- 只有分类名或搜索框，还没有菜品和价格。
- 购物车、订单确认、支付页、开票页。
- 页面正在加载或白屏。

### unqualified
要有清楚、可见的证据表明本轮拿不到菜单，而不是“暂时没成功”。

常见证据：
- 明确提示扫码点餐服务已关闭，且页面没有查看菜单的入口。
- 明确要求到店后再扫码点餐。
- 明确提示二维码失效、小程序停止服务或门店未配置菜单。
- 页面明确写暂无菜单/暂无菜品，且重试或刷新后仍一样。

不算 unqualified：
- 打烊但菜单可见 → success。
- 提示暂时无法下单，但有“查看菜单/进入点餐”入口 → 继续。
- 白屏、加载慢、网络提示 → 先等待或重试；仍不行再 needs_review。
- 点击没反应、弹窗关不掉、需要登录、页面归属不明 → needs_review。
- 菜品很少、店名不全 → 不影响 success。

### needs_review
合理尝试后仍然无法确定：
- 强制手机号 + 验证码，无法跳过。
- 持续白屏或一直加载，多次等待仍无内容。
- 打开的页面与本轮二维码关系不明。
- 工具连续失败、窗口反复被拒绝。
- 弹窗无法消除，页面卡在中间状态。

## 二、常见页面怎么处理

- 欢迎页/广告页：寻找“开始点餐”“进入菜单”“我知道了”等入口；广告可以关闭或跳过。
- 人数选择：按任务给出的用餐人数选择；没有对应数字时选最接近的可选项，然后确认。
- 隐私/授权弹窗：以消除阻碍为目标，允许、拒绝、同意、关闭都可以，不需要纠结选哪个。
- 系统通知弹窗：优先拒绝或关闭。
- 定位请求：可以拒绝；如果拒绝后无法继续，再允许并重新观察。
- 加载中：wait 两到三次，每次 1–2 秒；不要连续快速重复点击。
- 点击没反应：重新观察截图，确认按钮状态后再点；允许重试同一位置，但不要盲目连点。
- 出现新的小程序窗口：先 `list_windows`，再 `switch_window` 到疑似本轮门店的窗口，然后按新截图重新判断。
- 页面有多个相似入口：优先选择“点餐/菜单/开始点餐”，不要进入会员、储值、外卖、商城等与菜单无关的入口。

## 三、交接时的注意事项

- `menu_box` 只框菜品列表区域，不要包含顶部状态栏、底部购物车栏。
- 只框当前截图中可见的部分，不推测滚动后的区域。
- 理由写实际观察到的内容，例如“已进入菜单，可见菜品与价格”，不要写推测。
